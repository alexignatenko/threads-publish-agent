# Threads Publishing Agent

Скилл для ИИ-агента, который ведёт аккаунт в Threads: планирует, пишет твоим голосом,
публикует через официальный Threads API, отвечает в комментариях и разбирает статистику.

Отдаёшь ИИ, говоришь «настрой» — дальше ИИ сам задаёт вопросы про ключи,
тон публикаций, формат и лимиты, всё записывает и начинает работать.

---

## Отдай это ИИ

Передай агенту такой запрос:

> Установи скилл для публикаций в Threads из репозитория
> `alexignatenko/threads-publish-agent` и настрой его. Задай мне все вопросы,
> которые нужны: ключи доступа, голос публикаций, формат, лимиты.

Дальше агент разберётся сам. Если хочешь понимать, что он сделает, или ставить руками —
выбери свой случай:

| Что у тебя | Как ставится | Что получаешь |
| --- | --- | --- |
| **Claude Code** — в терминале, в приложении Claude, в редакторе кода через расширение | Плагином **(рекомендовано)** или копированием папки скилла | Плагином: обновление командами, 6 коротких команд `/threads:*`, выключатель. Копированием: всё то же, кроме этих трёх удобств |
| **Другой агент**, который умеет читать файлы и запускать команды в терминале | Копированием папки скилла | Полный скилл: онбординг, голос, публикации, аналитика. Без команд `/threads:*`, обновляешь сам |
| **ИИ без доступа к терминалу** — чат, в котором нельзя запускать команды | Не подойдёт | Скиллу нужно запускать Python и обращаться к API Threads. Без выполнения команд это не работает |

### Плагином — рекомендованный способ

В терминале:

```bash
claude plugin marketplace add alexignatenko/threads-publish-agent
claude plugin install threads
```

Скачивать ничего не нужно, файлы придут с GitHub. Подойдёт любой терминал, где доступна
команда `claude`. Плагин появится в следующей сессии.

Команды для обновления плагина. Первая перечитывает каталог, вторая обновляет сам плагин:

```bash
claude plugin marketplace update threads-publish-agent
claude plugin update threads
```

### Копированием папки скилла

Сначала скачай файлы репозитория: кнопкой **Code → Download ZIP** на GitHub и распакуй,
либо `git clone`.

Дальше либо попроси агента — «установи скилл для публикаций в Threads», он сделает это сам.
Либо выполни сам, из папки репозитория:

```bash
mkdir -p ~/.claude/skills
cp -r skills/threads-publishing ~/.claude/skills/
python3 ~/.claude/skills/threads-publishing/scripts/threads.py selftest
```

`~/.claude/skills/` — место, где скиллы ищет Claude Code. Другой агент может искать
в другом каталоге: положи папку туда, где он читает инструкции, и дай ему прочитать
`SKILL.md`. Внутри — маршрутизация по задачам, в `references/` подробности,
в `scripts/threads.py` весь доступ к API.

### Первый запуск

Командой — `/threads:setup` у плагина, `/threads-publishing` при установке копированием.
Или просто: **«настрой публикации в Threads»**.

Скилл дальше сам проведёт онбординг: поможет создать приложение в Meta for Developers,
попросит ключи и токен, спросит про тон публикаций, формат и лимиты. Заранее готовить
ничего не нужно.

## Что он умеет

| | |
| --- | --- |
| **Онбординг** | Проводит установку разговором: помогает создать приложение в Meta for Developers, получает токен, сохраняет его в файл с правами 600, собирает профиль голоса и правила публикации. |
| **Голос** | Интервью о тоне, темах, запретах и стоп-словах + разбор твоих текстов. Результат — файл `voice.md`, который читается перед каждым постом. |
| **Написание** | Посты с учётом лимита 500 символов, цепочки (thread chains), карусели, alt-тексты, ссылки-превью, темы (topic tags). |
| **Планирование** | Рубрики, ритм, банк идей, недельный план. Локальная очередь отложенных публикаций с автозапуском через cron. |
| **Комментарии** | Читает ответы и упоминания, раскладывает по корзинам (вопросы / спор / спам), готовит ответы, скрывает спам — с твоим подтверждением. |
| **Аналитика** | Метрики постов и аккаунта, сравнение рубрик по вовлечению, применимые выводы, а не дашборд. |
| **Подстраховка** | Ничего не публикуется без явного подтверждения текста. Суточные лимиты, стоп-слова, предпросмотр точных параметров запроса, журнал всего опубликованного. |

## Что понадобится

- **Python 3.8+** — уже есть почти везде. Внешних зависимостей нет, `pip install` не нужен.
- **Аккаунт Threads** и **аккаунт Facebook** для доступа в Meta for Developers.
- **Приложение в Meta for Developers** — бесплатно, создаётся один раз за 10–15 минут.
  ИИ проведёт по шагам; ты только нажимаешь кнопки в браузере и присылаешь токен.
  Своего домена и ключей приложения не нужно.
- **ИИ-агент с доступом к файлам и терминалу** — Claude Code или любой другой, умеющий читать
  скиллы и запускать команды.

Публиковать можно в свой аккаунт сразу, пока приложение в режиме разработки. Публикация от
имени других людей требует App Review у Meta — это отдельная история, для личного аккаунта
не нужна.

## Как этим пользоваться

Обычными словами, скилл подхватится сам:

- «напиши пост про то, как я переписал сборку»
- «составь контент-план на неделю»
- «поставь этот пост на вторник на 9:15»
- «что там в комментариях под последними постами»
- «как зашёл вчерашний пост»
- «сделай цепочку из трёх постов про эту ошибку»

Или командами: `/threads:write`, `/threads:plan`, `/threads:publish`, `/threads:inbox`,
`/threads:stats` — они есть, если скилл установлен плагином. При установке копированием
работает `/threads-publishing` и обычные формулировки выше.

## Безопасность

- **Публикация только с подтверждением.** Агент показывает текст, ты говоришь «публикуй».
  Без флага `--yes` скрипт физически не отправляет запрос — возвращает предпросмотр.
- **Публикация необратима.** Threads API не умеет ни редактировать, ни удалять посты.
  Поэтому подтверждение включено по умолчанию, и агенту велено не предлагать его отключать.
- **Секреты лежат локально.** `~/.threads-agent/profiles/<профиль>/credentials.json`, права 600,
  никуда не отправляются. В выводе команд токены замаскированы. Можно передавать через
  переменные окружения (`THREADS_ACCESS_TOKEN` и др.) — тогда на диск они не пишутся вовсе.
- **Суточные лимиты и стоп-слова** — в настройках `safety`. Локальный лимит строже лимита API
  и существует, чтобы агент не устроил спам-волну.
- **Журнал.** Всё, что публиковал агент, пишется в `history.jsonl` со ссылками.

## Где что лежит

После установки — данные, они же настройки:

```
~/.threads-agent/profiles/default/
├── config.json       # настройки: лимиты, тайм-зона, кто может отвечать
├── credentials.json  # app_id, app_secret, токен (chmod 600)
├── voice.md          # профиль голоса
├── plan.md           # контент-план и банк идей
├── queue.json        # очередь отложенных публикаций
└── history.jsonl     # журнал публикаций
```

Несколько аккаунтов — несколько профилей: `threads.py --profile brand …`.

Сам скилл:

```
skills/threads-publishing/
├── SKILL.md              # точка входа: правила и маршрутизация
├── references/           # подробности, читаются по необходимости
│   ├── setup.md          # онбординг: приложение, токен, интервью
│   ├── voice.md          # профиль голоса

│   ├── planning.md       # контент-план и очередь
│   ├── replies.md        # комментарии и модерация
│   ├── analytics.md      # метрики и выводы
```

## CLI напрямую

Скрипт работает и без ИИ. Всё печатает JSON.

Путь к скрипту разный: при установке копированием — в `~/.claude/skills/`, у плагина —
в кэше плагинов. Эта строка находит его в обоих случаях:

```bash
T="python3 $(find ~/.claude -name threads.py -path '*threads-publishing*' | head -1)"

$T doctor                                   # диагностика + продление токена
$T post --text "Привет, Threads"            # предпросмотр
$T post --text "Привет, Threads" --yes      # публикация
$T chain --file chain.json --yes            # цепочка
$T queue add --at 2026-10-02T09:15:00+03:00 --text "Утренний пост"
$T queue run --yes
$T insights --media-id 17900000000000000
$T selftest                                 # оффлайн-проверка, сеть не нужна
```

Полный список команд — `references/api.md` или `$T --help`.

## Проверки

Пошаговый план проверки на живом аккаунте — в [TESTING.md](TESTING.md), включая случай,
когда токен уже используется другим сервисом.

Автотесты сеть не используют: Threads API замокан. Запускаются из папки репозитория,
если он скачан:

```bash
python3 skills/threads-publishing/scripts/threads.py selftest   # сборка и валидация запросов
python3 tests/test_publish_flow.py                              # боевой путь публикации
```

`selftest` проверяет валидацию: лимит 500 символов, запреты в темах, размеры карусели,
стоп-слова, маскировку секретов. `tests/test_publish_flow.py` проверяет то, что нельзя
проверить иначе не публикуя по-настоящему: что предпросмотр не делает ни одного запроса,
что цепочка связывает посты через `reply_to_id`, что карусель собирается из детей,
что видео ждёт обработки, что суточный лимит останавливает публикацию и что оборванная
цепочка не публикуется заново.

## Ограничения Threads API

Это ограничения платформы, не скилла:

- нельзя редактировать и удалять опубликованное;
- нет публикации по расписанию — очередь локальная, её запускает cron или ты сам;
- 500 символов на пост, 250 постов и 1000 ответов за 24 часа;
- медиа только по публичным HTTPS-ссылкам, локальные файлы загружать нельзя;
- нет опросов;
- публикация в чужие аккаунты — только после App Review у Meta.
