# Комментарии: чтение, ответы, модерация

Читай, когда пользователь просит посмотреть комментарии, ответить людям или разобраться
со спамом.

Нужны разрешения токена: `threads_read_replies` для чтения, `threads_manage_replies`
для ответов и скрытия. Если их нет, API вернёт ошибку доступа — токен придётся перевыпустить
с нужными scope (`references/setup.md`).

---

## Собрать инбокс

```bash
$T list --limit 10                              # последние посты — из них берём id
$T replies --media-id <MEDIA_ID>                # ответы верхнего уровня к посту
$T replies --media-id <MEDIA_ID> --conversation # вся ветка, включая ответы на ответы
$T replies --mine --limit 50                    # что отвечал сам пользователь
$T replies --mentions --limit 25                # где его упомянули
```

Разумный порядок: взять последние 3–5 постов, собрать по ним ответы, отбросить те, где
последний ответ уже от пользователя (`username` совпадает с `account.username` в конфиге).

---

## Как разбирать

Раскладывай по четырём корзинам и **показывай пользователю сводку, а не сырой JSON**:

| Корзина | Что делать |
| --- | --- |
| Благодарности и короткие реакции | Отвечать не обязательно. Если пользователь разрешил простые ответы — коротко и по-человечески, без шаблона «Спасибо за комментарий!». |
| Содержательные вопросы | Готовь ответ, показывай пользователю. Требуют фактов, которых у тебя может не быть — спрашивай, не выдумывай. |
| Спор, критика, претензия | **Всегда на подтверждение.** Никогда не отвечай сам. Предложи вариант — спокойный, без защитной интонации. |
| Спам, оскорбления, реклама | Предложи скрыть. Скрытие делает `hide`, решение принимает пользователь. |

Сводка выглядится примерно так:

```
Под постом «Почему я перестал…» (12 ответов):
  3 вопроса по делу — подготовил ответы, покажу
  1 спор про бенчмарки — нужно твоё решение
  2 спама со ссылками — предлагаю скрыть
  остальное — реакции, отвечать не нужно
```

## Отвечать

```bash
$T reply --to <MEDIA_ID или REPLY_ID> --text "Текст ответа"        # предпросмотр
$T reply --to <MEDIA_ID или REPLY_ID> --text "Текст ответа" --yes  # отправка
```

Ответы считаются отдельно от постов: лимит API — 1000 ответов за 24 часа, локальный —
`safety.max_replies_per_day`.

Правила ответов:

1. **Тон тот же, что в постах** — читай `voice.md`. Ответы часто видны чаще самих постов.
2. **Коротко.** Ответ длиннее исходного комментария выглядит как спор с самим собой.
3. **Не начинай с «Спасибо за комментарий»** и других обслуживающих формул, если это не
   манера пользователя.
4. **Не повторяй мысль поста** другими словами — это раздражает. Либо добавь что-то, либо
   не отвечай.
5. **Один ответ на человека в ветке.** Не превращай комментарии в переписку от лица пользователя,
   пока он сам этого не попросил.
6. **Никогда не отвечай на спорное без подтверждения**, даже если ответ кажется безобидным.
   Публичная перепалка от лица пользователя — то, что нельзя отменить.

Ответ на ответ: передавай в `--to` id того ответа, на который отвечаешь, а не id поста —
иначе ответ встанет на верхний уровень и человек его не увидит как обращённый к нему.

## Скрывать

```bash
$T hide --reply-id <REPLY_ID>            # предпросмотр
$T hide --reply-id <REPLY_ID> --yes      # скрыть
$T hide --reply-id <REPLY_ID> --unhide --yes  # вернуть
```

Скрытие обратимо, но **всё равно требует решения пользователя**, если он не дал заранее
явное разрешение скрывать очевидный спам. Автоматически скрывать критику нельзя ни при каких
настройках: критика и спам — разные вещи, и путать их значит подчищать ленту от неудобного.

---

## Регулярный разбор

Если пользователь просит «следить за комментариями», это значит: при каждой сессии собирать
инбокс по последним постам и приносить сводку. Никакого фонового опроса — ты работаешь тогда,
когда тебя позвали.

Если он хочет именно фоновую проверку, объясни: этот скилл так не умеет, нужен внешний
планировщик, который будет запускать сессию (например, cron + `claude -p`). Не обещай того,
чего скилл не делает.
