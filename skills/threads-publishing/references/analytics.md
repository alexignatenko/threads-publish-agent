# Аналитика: что сработало и что с этим делать

Читай, когда пользователь спрашивает «как зашло», «какая статистика», «что публиковать чаще».

Нужно разрешение токена `threads_manage_insights`. Без него API вернёт ошибку доступа.

---

## Команды

```bash
# Метрики одного поста.
$T insights --media-id <MEDIA_ID>

# Метрики аккаунта за период.
$T insights --since 2026-09-01 --until 2026-09-30

# Только нужные метрики.
$T insights --media-id <MEDIA_ID> --metrics views,likes,replies

# Что публиковал этот агент (локальный журнал со ссылками).
$T history --limit 50
```

## Метрики

**По посту:** `views` (показы), `likes`, `replies`, `reposts`, `quotes`, `shares`.

**По аккаунту:** те же плюс `followers_count`. Часть метрик аккаунта доступна только за
ограниченный период назад, и `since/until` задаются как даты или unix-время.

Чего в API нет: сохранений, просмотров профиля по постам, источников трафика, демографии
по конкретному посту. Не придумывай эти цифры и не выводи их «оценочно».

---

## Как читать

Считай только то, что сравнимо. Полезные сравнения:

- **Вовлечение, а не показы.** `(likes + replies + reposts) / views` — показывает, задел ли
  пост, а не сколько раз его пролистали. Показы сильно зависят от алгоритма и времени.
- **Ответы отдельно.** Высокие `replies` при средних `likes` — пост задел за живое или вызвал
  спор. Это важнее лайков, если цель — разговор.
- **Репосты и цитаты** — сигнал, что пост вынесли за пределы своей аудитории. Самый ценный,
  самый редкий.
- **Первый пост цепочки против остальных.** Если у первого показы в разы выше — цепочку
  не дочитывают, значит она длинная или первый пост обещает не то.

Чего **не** делай:

- не сравнивай пост, которому два часа, с постом, которому неделя;
- не делай выводов по одному посту — нужно минимум 5–7 в одной рубрике;
- не объясняй разброс задним числом («зашло, потому что была картинка»), если не сравнил
  с постами без картинки;
- не превращай отчёт в дашборд на экран — пользователю нужно 3 строки и вывод.

---

## Формат отчёта

Коротко, с выводом, который можно применить:

```
Сентябрь, 14 постов
Лучше всего: разборы ошибок — вовлечение 7,2% против 3,1% в среднем
Хуже всего: анонсы и ссылки — 1,4%, репостов нет
Цепочки: первый пост собирает втрое больше показов, чем последний — читают не до конца
Вывод: больше разборов, цепочки короче (3 поста вместо 5), анонсы — реже
```

Дальше предложи одно-два изменения в контент-плане и, если пользователь согласен, обнови
`plan.md` и рубрики (`references/planning.md`). Наблюдения о форме («короткие заходы работают
лучше») дописывай в `voice.md` — иначе следующая сессия про них не узнает.

## Связь с журналом публикаций

`$T history` хранит локально всё, что публиковал агент: id, тип, время, ссылку и текст.
Это удобнее, чем `list`, когда нужно сопоставить метрики с рубрикой из плана — в API
разметки по рубрикам нет, а в журнале и очереди есть `note`.

Порядок для полноценного разбора: взять `history` за период → для каждого `media_id`
запросить `insights` → сгруппировать по рубрике из `note` → сравнить.
