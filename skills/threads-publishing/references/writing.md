# Как писать посты для Threads

Читай перед тем, как написать любой текст для публикации. Профиль голоса (`voice.md`) —
про то, *как* звучит пользователь. Этот файл — про то, что работает *в Threads* как площадке.
Если они противоречат, побеждает профиль голоса.

---

## Ограничения площадки

| Что | Значение |
| --- | --- |
| Текст поста и ответа | 500 символов |
| Alt-текст к медиа | 1000 символов |
| Карусель | 2–20 элементов (фото/видео) |
| Тема (topic tag) | одна на пост, 1–50 символов, без `.` и `&` |
| Ссылка-превью | одна, из первой ссылки в тексте либо заданная явно |

Считай символы. 500 — это жёсткий предел API: CLI откажется публиковать более длинный текст
ещё до обращения к сети, но лучше не доводить. Практически читаемый пост — заметно короче.

Что API **не умеет**: редактировать опубликованное, удалять, публиковать по расписанию,
ставить опросы, публиковать в чужие аккаунты без App Review.

---

## Форма поста

Threads читают в ленте, быстро, с телефона. Работает:

- **Первая строка — самостоятельная.** Она решает, развернут ли пост. Не «Сегодня хочу
  поговорить о…», а сразу мысль или наблюдение.
- **Одна мысль на пост.** Два тезиса в одном посте — это цепочка из двух постов.
- **Конкретика вместо обобщений.** «Переписал сборку, стало 40 секунд вместо 6 минут» живёт,
  «оптимизация процессов важна» — нет.
- **Разговорный ритм.** Короткие предложения, обычные слова, можно начать с союза.
- **Пустая строка вместо длинного абзаца.** Три строки подряд — уже стена.

Не работает и выдаёт ИИ-текст с первого взгляда:

- разгон на две строки перед сутью («В современном мире…», «Давайте разберёмся…»);
- перечисление из трёх однотипных пунктов ради ритма;
- эмодзи вместо маркеров списка, эмодзи в начале строки;
- вывод-резюме в конце того, что и так было сказано;
- «делимся», «рады представить», «спойлер:», «а теперь самое интересное»;
- обилие тире там, где хватает точки;
- фальшивая скромность («возможно, я не прав, но…») и фальшивая сенсация одновременно.

Если в скилле доступны `anthropic-skills:human-writing` или `anthropic-skills:avoid-ai-writing` —
прогони черновик через них перед показом пользователю.

## Цепочки

Цепочка — несколько постов, где каждый следующий является ответом на предыдущий. Так в Threads
подают то, что не влезает в 500 символов.

Правила:

1. **Первый пост должен работать в одиночку.** Его увидят в ленте отдельно от остальных.
   Он содержит тезис целиком, а не «сейчас расскажу, как я…».
2. **Каждый следующий пост — законченный шаг**, а не продолжение предложения с середины.
3. **Не нумеруй «1/5», если пользователь сам так не делает.** Счётчик обещает лонгрид и
   отпугивает; исключение — если это его узнаваемая манера.
4. **3–5 постов.** Больше — либо статья, либо две темы.
5. **Порядок необратим.** Цепочка публикуется последовательно, переставить потом нельзя.

Формат файла для публикации — `assets/chain.example.json`:

```json
{
  "reply_control": "everyone",
  "posts": [
    { "text": "Первый пост: тезис, который работает сам по себе." },
    { "text": "Второй: что именно сделал." },
    { "text": "Третий: чем кончилось и что из этого следует." }
  ]
}
```

В каждом элементе можно задать `image_url`, `video_url`, `alt_text`, `link_attachment`,
`topic_tag`. Публикация: `$T chain --file chain.json --yes`.

Если цепочка оборвалась посередине, CLI вернёт `"partial": true` и список уже опубликованных
постов. **Не публикуй её заново.** Продолжи с последнего id: `$T post --reply-to <id> --text "…" --yes`.

## Медиа

- Ссылки на медиа должны быть **публичными HTTPS-URL**. API забирает файл сам, локальные
  файлы загружать нельзя. Если у пользователя картинка на диске — скажи, что её нужно
  сначала выложить куда-то с прямой ссылкой.
- **Alt-текст пиши всегда**, когда есть картинка. Описывай, что на ней, а не повторяй подпись.
- Видео обрабатывается на стороне Meta; CLI сам ждёт готовности (по умолчанию до 300 секунд).
- Карусель — 2–20 медиа, подпись одна на всю карусель, alt-тексты по порядку:
  `$T carousel --image URL1 --image URL2 --text "Подпись" --alt-text "первая" --alt-text "вторая" --yes`

## Темы, ссылки, гео

- **topic_tag** — одна тема на пост, передаётся без `#`. Ставь, только если пользователь
  подтвердил, что пользуется темами.
- **link_attachment** — явная ссылка-превью для текстового поста. Если не задать, превью
  сделается из первой ссылки в тексте. Для постов с картинкой не применяется.
- **reply_control** — кто может отвечать: `everyone`, `accounts_you_follow`, `mentioned_only`.
  Задаётся при создании и **после публикации не меняется**. Берётся из `defaults.reply_control`,
  если не указать.
- **--countries** — гео-гейт: пост увидят только в перечисленных странах (ISO-коды: `RU,KZ`).
  Нужно редко, спрашивай, а не решай сам.

## Порядок работы над текстом

1. Прочитай `voice.md`.
2. Уточни то, чего не знаешь: цифры, названия, детали. Не додумывай.
3. Напиши 1–3 варианта, если пользователь не задал жёстких рамок. Разные заходы, не
   перефразировки одного и того же.
4. Посчитай символы. Покажи текст **как он уйдёт** — без markdown-разметки, без «вот вариант:».
5. Прогони по стоп-листу и запретам из `voice.md`.
6. Предпросмотр без `--yes`, если пост с медиа или цепочкой — увидишь, что именно уйдёт в API.
7. После согласия — `--yes`. Отдай ссылку.

Черновики, которые пользователь хочет сохранить, складывай в файлы рядом с проектом
или ставь в очередь (`references/planning.md`), а не держи в переписке.
